## What to build

T06：恢复训练并保留一致的日志与结果。

研究者能启动独立运行、查看文件/TensorBoard指标，并从最近完成epoch继续同一实验，保留当时best与清晰的结果历史。以T01的场景闭环验证这一行为，再由汇合验收确认两个任务均适用。

## Acceptance criteria

- [ ] 新运行使用含任务、变换、seed、UTC时间、短随机串的唯一标识，不静默覆盖；恢复必须显式指定既有运行，最终合并配置和环境/代码标识可追溯。
- [ ] 保存best权重及last完整训练状态，包含模型、优化器、epoch、当时最佳指标/位置和随机状态；恢复至原目标总轮数，不额外追加30轮。
- [ ] 恢复核对任务、变换、标签映射、模型/优化器参数、seed、train/val清单标识、预处理/模型版本；不兼容明确拒绝，路径/设备变化可记录后允许，不宣称跨设备逐位一致。
- [ ] 超过last已提交完整epoch的指标归档后续写，不重复有效epoch，TensorBoard遵循相同恢复点并保持best可定位；既有历史产物保留。
- [ ] 每epoch记录训练/验证Loss、验证Accuracy、主Macro-F1、适用的固定47辅助指标、学习率、耗时、样本数；每50训练step另记训练Loss。最终配置、JSONL指标、JSON汇总、逐类/混淆矩阵CSV和同run_id的TensorBoard可读取。
- [ ] 使用小构造数据的公开命令验证新运行、完整epoch中断/续训、配置不兼容拒绝和超前指标归档；在相同CPU模式下比较恢复与连续运行的可见结果，不改变真实CPU四配置各1epoch的验收预算。
- [ ] 本票只扩展运行状态/日志边界，遵守T01通用任务/清单/模型契约；不改动Primitive区间或raw/log1p选择策略，不人为等待T02/T05。
