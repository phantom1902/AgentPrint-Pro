## What to build

T03：按完整方向与流量质量规则生成样本。

研究者对包含多协议、IPv6、背景流量或捕获缺陷的输入运行prepare后，获得符合已确认观察范围的样本，或能够解释的排除记录；生成的有效场景缓存仍能被训练评估闭环消费。该ticket从T01的成功路径扩展真实输入边界，不依赖Primitive标注实现。

## Acceptance criteria

- [ ] 在完整Episode上按唯一RFC1918初始SYN发起端且包参与数唯一第一判定IPv4；无候选、多候选或条件冲突排除并记录，不增加覆盖率阈值、地址字典序消歧或UDP/53回退。
- [ ] 选定IPv4的源MAC唯一时，关联同一源MAC发出的IPv6单播源地址；排除未指定地址和组播地址，多MAC/地址冲突不关联，不把多播目的MAC视作运行端下行身份。
- [ ] 仅源属于运行端为上行、仅目的属于运行端为下行，两端均属于或均不属于时跳过并计数；保存规则版本、候选/选定地址和证据，供同一Episode的全部样本复用。
- [ ] 纳入IP长度可靠可读的IPv4/IPv6各协议，包含UDP/ICMP，保留ACK、SYN/FIN和逐包观察重传；非IP不纳入，不以运输层载荷完整作为IP统计前提。
- [ ] 载荷截断但IP长度可靠可读时计入并记录；IP头不可读跳过；记录流损坏则整Episode排除，不能提交可用前缀缓存。空捕获、零时长、无可用方向包产生明确排除记录。
- [ ] 解析依据实际链路类型，未知或不支持格式明确报告，不静默当作Ethernet；预期质量排除继续，未预料程序错误停止并保留既有完成产物。
- [ ] 构造捕获经公开prepare命令验证地址竞争、IPv6/MAC关联、多播、非TCP、截断/损坏和边界统计；有效产物可进入T01训练评估，排除原因和计数可检查。真实数据抽样只用作补充证据，不宣称方向真值准确率。
