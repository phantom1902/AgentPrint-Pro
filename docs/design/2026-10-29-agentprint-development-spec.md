## 1. 交付范围

## 3. MTAM

观察样本时间范围内、能确定方向的运行端全部连接，纳入能可靠读取 IP 总长度的 IPv4/IPv6 包，不仅限于 TCP。保留 ACK、SYN/FIN 和实际观察到的 TCP 重传；ARP 等非 IP 包不纳入。

字节量采用 IP 包总长度：IPv4 total length；普通 IPv6 为 40 字节固定头加 payload length（Q8）。按 Q19/Q20 记录不可用包和方向缺失，不用帧长、捕获长度或载荷长替代。按 Q41，IP 总长度可靠可读的载荷截断包仍计入并记录截断；IP 头不可读则跳过该包；PCAP 记录流损坏到不能可靠继续解析则排除该 episode 并记录。按 Q42，预处理未预料程序异常停止命令、保留已完成产物并报告，预期质量问题仍按已确认规则跳过。

每个 episode 的完整捕获时间范围、每个片段的完整标注区间各自等分成 1800 槽，不以过滤后首末包收缩区间（Q10）。按 Q40，内部边界包归新槽，整个 episode 的捕获终点进入最后槽，片段终点按有效末片段规则处理。

张量尺寸为 `[B,2,2,1800]`（Q1/Q10）。Q46 已固定通道和方向索引顺序：

- 统计通道：包数、IP 字节量。
- 方向：上行、下行。
- 时间：1800 槽。

统计为空的槽数值为零。raw 和逐元素 `log1p(x)=ln(1+x)` 由两个任务各自通过验证集选择（Q11）。缓存使用分片 .npy（Q26），保存 uint64 原始整数统计，训练读取后转 float32，再按配置施加 log1p（Q30）。按任务及 split 分开，每 1024 个有效样本一片，末片可不足（Q31）；每个样本保持完整，文件形状为 [n,2,2,1800]，n≤1024。此处的文件分片与 batch_size=200 独立。

Q32 已确认预处理支持中断后继续，复用已完成且兼容的产物，仅补未完成部分，数据或配置不兼容时报告原因。Q38 采用预处理版本、配置、文件清单及 PCAP 路径/大小/mtime 校验，对小标注与端点元数据做内容哈希，不每次全量计算 PCAP SHA256。该方案不能识别大小和 mtime 均不变的 PCAP 内容替换。按 Q39，以完整 .npy 分片为完成单位，未提交分片重建，已完成且兼容分片复用；不额外保存 episode 级临时 MTAM。

存储估算：每个 uint64 原始 MTAM 占 57600 字节。若已清点的 56368 条完整标注和 3114 个 PCAP 都生成候选样本，两任务未过滤 MTAM 约 3.43 GB，不含清单、文件头、模型、日志和临时产物；实际有效样本需筛选后统计。按 1024 样本分片不复制样本，不代表原始 PCAP 存储翻倍；Q39 已选按完整分片恢复，不另存一套 episode 级临时 MTAM。

## 4. CNN 的具体搭建

依据 Q1 继承 Robust Fingerprinting 的 RF 参考源码。首个 Conv2d 的实际构造参数从 1 输入通道改为 2，最后类别输出改为 K=5 或 47，保留其余参考结构、BN、激活、Dropout 和初始化方式。不能仅修改未参与构造的通道属性。

关键形状如下，B 为批大小：

| 阶段 | 主要参数 | 输出形状 |
|---|---|---|
| 输入 | 两统计、两方向、1800 槽 | `[B,2,2,1800]` |
| 2D 卷积两层 | 2→32→32；核 (3,6)，padding (1,1)，各接 BN/ReLU | `[B,32,2,1794]` |
| 2D 池化 | MaxPool (1,3)，Dropout 0.1 | `[B,32,2,598]` |
| 2D 卷积两层 | 32→64→64；同上卷积参数，各接 BN/ReLU | `[B,64,2,592]` |
| 2D 池化 | MaxPool (2,2)，Dropout 0.1 | `[B,64,1,296]` |
| 参考 reshape | 保留 `view(B,32,-1)` | `[B,32,592]` |
| 1D 卷积两层 | 32→128→128；核 3，padding 1，各接 BN/ReLU | `[B,128,592]` |
| 1D 池化 | MaxPool 3，Dropout 0.3 | `[B,128,197]` |
| 1D 卷积两层 | 128→256→256；同上卷积参数，各接 BN/ReLU | `[B,256,197]` |
| 1D 池化 | MaxPool 3，Dropout 0.3 | `[B,256,65]` |
| 1D 卷积两层 | 256→512→K；同上卷积参数，各接 BN/ReLU | `[B,K,65]` |
| 输出池化 | AdaptiveAvgPool1d(1)，flatten | `[B,K]` |

`64×1×296 = 32×592`，原参考的 reshape 与后续 32 输入通道相容，无需增加投影层。参考最后类别卷积也接 BN/ReLU，首版保留；模型不含 softmax，输出类别分数直接送入交叉熵，展示概率时才做 softmax。

上述形状已按源码和尺寸公式核对，尚非运行测试结果。实现阶段必须实际验证两个输出头的前向、损失和反向计算。

模型来源：[RF/models/RF.py](https://github.com/robust-fingerprinting/RF/blob/master/RF/models/RF.py)。参考源码 SHA256（UTF-8、换行统一为 LF）：`4cf9ff1a71a3601aeab61756327467add251475fa3bfd9c19eeb43e658effa19`，本次重新计算与已保存来源清单一致。这是有来源的 RF 结构适配，不宣称逐参数复现 AgentPrint。

## 5. 损失、训练及模型选择

两个任务分别使用普通、无类别权重的交叉熵。对类别分数 z 和真实类别 y：

`L = mean(log(sum(exp(z))) - z[y])`

实现使用 PyTorch `CrossEntropyLoss` 的数值稳定形式，不手工先做 softmax，不构造联合损失。

训练参数沿用 RF 起点：Adam，初始学习率 5e-4，weight_decay=1e-3，batch_size=200，30 epochs。每轮开始按 `lr(e)=5e-4×0.2**(e/30)` 设置学习率，e=0…29。硬件所需的参数调整必须记录并在对应 raw/log1p 比较中保持一致。

每轮验证，主 Macro-F1 选择 checkpoint；主 Macro-F1 仅平均固定有效清单中有真实样本的类别。片段任务同时报告固定 47 类、缺类计零的辅助 Macro-F1，分类头保持 47 类。按 Q13/Q14 同步报告 Accuracy、逐类支持数、覆盖率和训练类缺失情况。Q35/Q51 均为 B：每 epoch 记录训练/验证 Loss、验证 Accuracy、主 Macro-F1、片段固定47辅助 Macro-F1、学习率、耗时、样本数，并每 50 个训练 step 增加一次训练 Loss。输出 resolved_config.yaml、metrics.jsonl、summary.json、per_class.csv、confusion_matrix.csv，以及 TensorBoard 实时曲线。运行目录 run_id 含任务/变换/seed/UTC时间/短随机串，TensorBoard 使用同一 run_id。

按 Q28，验证主 Macro-F1 同分保留先出现候选：checkpoint 取较早 epoch，输入配置按 raw→log1p 固定顺序，配置同分选 raw。测试集不参与选择（Q11/Q13）。按 Q44=B，四个预声明配置均报告各自验证最优 checkpoint 的测试结果，并标记验证集选出的每任务主配置；正式训练仍为 4 次。

首版训练预算为 seed=42，两个任务×raw/log1p×一个种子，共 4 次正式训练（Q16）。仅单种子，不报告多种子均值或标准差。Q33 保存 best 权重与 last 完整训练状态，后者含模型、优化器、epoch、最佳指标及随机状态，支持从最近完成的 epoch 继续至总计 30 轮。

Q52 校验任务、输入变换、类别映射、模型/优化器参数、seed、训练/验证清单标识和预处理/模型实现版本；允许路径/设备等运行项变化并记录，跨设备不宣称逐位相同。以 last 对应完整 epoch 为恢复点，同时保留当时 best 的定位及指标；超过恢复点的未提交指标归档后再续写，TensorBoard 避免有效 epoch 重复。

Q53 采用 FP32，关闭 AMP/TF32/cuDNN benchmark，固定 seed 并启用可用的确定性执行要求；预处理单进程，DataLoader num_workers=0，正式配置依次运行。遇到 OOM、非有限损失或不支持所要求模式时停止并报告，不自动改变 batch size、精度或训练参数。
