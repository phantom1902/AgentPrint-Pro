## 1. 交付范围

在现有仓库新增独立 `agentprint` 模块和命令行入口，提供数据预处理、训练和评估功能。

| 任务 | 一个样本 | 标签 | 输出 |
|---|---|---|---|
| 场景分类 | 完整 episode 的捕获流量 | 五类场景目录标签 | 5 类分数 |
| 片段分类 | 按已有标注起点构造的给定区间 | 当前 N001–N047 primitive 标签 | 47 类分数 |

两个任务共用适用的解析、MTAM 和网络定义，分别构建样本清单、训练、保存权重和评估。首版不增加风险分类、联合训练或自动边界检测。

## 2. 数据适配

- 数据根目录：`/root/autodl-tmp/ant-workspace/data/raw/ANT`。保持官方 train/val/test，不重新随机划分。
- 场景标签为 artifact_processing、general_knowledge、scientific_evidence、business_services、security_testing；片段只采用当前 N001–N047，不混入旧 G 类标签。
- PCAP 为 episode 级捕获。每个片段从当前标注起点到下一个起点，最后一段到捕获结束（Q3）。区间左右端点的具体包归属规则是草案提议，仍待工程确认。
- 同起点组全部排除；排除范围到下一个不同起点，末组到捕获结束。保留其他有效片段，不跨被排除区间拼接。
- 排除无可用包、零时长或无法可靠对齐的片段，记录原因；不增加最少包数或最短时长阈值，不猜测时间偏移。
- 缺少片段标注或无法对齐日志，不自动排除其场景分类资格。两个任务分别报告有效样本与排除情况。
- 使用数据已有的明确运行端信息判定上下行。缺失则跳过并统计，不另建端点推断或人工补录流程；不把“数据一般应该有”当作已核验事实。
- 待确认提议：空捕获、没有可用方向包或捕获时长为零的 episode 记录后跳过，不以全零输入代替。Q6 已确认的是片段规则，此处对场景样本的扩展仍需磋商。
- 所有排除仅作用于派生样本清单，不删除或改写原始数据。

按 Q5–Q7/Q14 报告有效/排除数量、原因、逐类支持数和覆盖率，各配置使用同一固定有效清单。清单存储格式和字段尚待确认；候选字段包括 episode 标识、划分、任务、类别、来源路径、区间、端点依据和质量状态。

## 3. MTAM

观察样本时间范围内、能确定方向的运行端全部连接，纳入能可靠读取 IP 总长度的 IPv4/IPv6 包，不仅限于 TCP。保留 ACK、SYN/FIN 和实际观察到的 TCP 重传；ARP 等非 IP 包不纳入。

字节量采用 IP 包总长度：IPv4 total length；普通 IPv6 为 40 字节固定头加 payload length（Q8）。按 Q19/Q20 记录不可用包和方向缺失，不用帧长、捕获长度或载荷长替代。抓包截断与记录损坏时是保留可读头部、排除单包还是排除样本，尚待工程确认；上一版给出的处理方式不是已确认规则。

每个 episode 的完整捕获时间范围、每个片段的完整标注区间各自等分成 1800 槽，不以过滤后首末包收缩区间（Q10）。恰好位于区间终点的包如何分配尚待工程确认。

张量尺寸为 `[B,2,2,1800]`（Q1/Q10）。以下通道和方向索引顺序为待确认提议：

- 统计通道：包数、IP 字节量。
- 方向：上行、下行。
- 时间：1800 槽。

统计为空的槽数值为零。raw 和逐元素 `log1p(x)=ln(1+x)` 由两个任务各自通过验证集选择（Q11）。缓存使用分片 .npy（Q26）；缓存内容、数值类型及变换施加位置待 Q30 确认，具体分片待 Q31 确认，断点复用待 Q32 确认。

## 4. CNN 的具体搭建

依据 Q1 继承 Robust Fingerprinting 的 RF 参考源码。首个 Conv2d 的实际构造参数从 1 输入通道改为 2，最后类别输出改为 K=5 或 47，保留其余参考结构、BN、激活、Dropout 和初始化方式。不能仅修改未参与构造的通道属性。

关键形状如下，B 为批大小：

| 阶段 | 主要参数 | 输出形状 |
|---|---|---|
| 输入 | 两统计、两方向、1800 槽 | `[B,2,2,1800]` |
| 2D 卷积两层 | 2→32→32；核 (3,6)，padding (1,1)，各接 BN/ReLU | `[B,32,2,1794]` |
| 2D 池化 | MaxPool (1,3)，Dropout 0.1 | `[B,32,2,598]` |
| 2D 卷积两层 | 32→64→64；同上卷积参数，各接 BN/ReLU | `[B,64,2,592]` |
| 2D 池化 | MaxPool (2,2)，Dropout 0.1 | `[B,64,1,296]` |
| 参考 reshape | 保留 `view(B,32,-1)` | `[B,32,592]` |
| 1D 卷积两层 | 32→128→128；核 3，padding 1，各接 BN/ReLU | `[B,128,592]` |
| 1D 池化 | MaxPool 3，Dropout 0.3 | `[B,128,197]` |
| 1D 卷积两层 | 128→256→256；同上卷积参数，各接 BN/ReLU | `[B,256,197]` |
| 1D 池化 | MaxPool 3，Dropout 0.3 | `[B,256,65]` |
| 1D 卷积两层 | 256→512→K；同上卷积参数，各接 BN/ReLU | `[B,K,65]` |
| 输出池化 | AdaptiveAvgPool1d(1)，flatten | `[B,K]` |

`64×1×296 = 32×592`，原参考的 reshape 与后续 32 输入通道相容，无需增加投影层。参考最后类别卷积也接 BN/ReLU，首版保留；模型不含 softmax，输出类别分数直接送入交叉熵，展示概率时才做 softmax。

上述形状已按源码和尺寸公式核对，尚非运行测试结果。实现阶段必须实际验证两个输出头的前向、损失和反向计算。

模型来源：[RF/models/RF.py](https://github.com/robust-fingerprinting/RF/blob/master/RF/models/RF.py)。参考源码 SHA256（UTF-8、换行统一为 LF）：`4cf9ff1a71a3601aeab61756327467add251475fa3bfd9c19eeb43e658effa19`，本次重新计算与已保存来源清单一致。这是有来源的 RF 结构适配，不宣称逐参数复现 AgentPrint。

## 5. 损失、训练及模型选择

两个任务分别使用普通、无类别权重的交叉熵。对类别分数 z 和真实类别 y：

`L = mean(log(sum(exp(z))) - z[y])`

实现使用 PyTorch `CrossEntropyLoss` 的数值稳定形式，不手工先做 softmax，不构造联合损失。

训练参数沿用 RF 起点：Adam，初始学习率 5e-4，weight_decay=1e-3，batch_size=200，30 epochs。每轮开始按 `lr(e)=5e-4×0.2**(e/30)` 设置学习率，e=0…29。硬件所需的参数调整必须记录并在对应 raw/log1p 比较中保持一致。

每轮验证，主 Macro-F1 选择 checkpoint；主 Macro-F1 仅平均固定有效清单中有真实样本的类别。片段任务同时报告固定 47 类、缺类计零的辅助 Macro-F1，分类头保持 47 类。按 Q13/Q14 同步报告 Accuracy、逐类支持数、覆盖率和训练类缺失情况。逐类指标文件、混淆矩阵等附加产物的格式尚待工程确认。

按 Q28，验证主 Macro-F1 同分保留先出现候选：checkpoint 取较早 epoch，输入配置按 raw→log1p 固定顺序，配置同分选 raw。测试集不参与选择（Q11/Q13）；只评估选中配置还是同时报告所有预先声明配置的测试结果，尚待后续磋商。

首版训练预算为 seed=42，两个任务×raw/log1p×一个种子，共 4 次正式训练（Q16）。仅单种子，不报告多种子均值或标准差。checkpoint 保存内容和训练恢复策略待 Q33 确认；未确认字段不作为默认实现。
