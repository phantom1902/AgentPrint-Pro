# AgentPrint 适配 ANT：设计磋商

状态：磋商中。本文记录已确认范围和待决问题，尚不是可执行的开发规格。

磋商方式：按用户要求，一次只提一个问题。

## 已确认

- 开发五类整 episode 场景分类、47 类给定片段分类两个独立任务。
- 方法依据为用户指定的 AgentPrint 论文，研究数据为现有 ANT。
- 片段来自已有标注；两个任务分别训练和评估。
- 给定片段采用当前标注起点到下一标注起点的区间，最后一段到 PCAP 结束；异常标注的处理另行决定。
- 重复起点只排除该组对应的不确定区间，保留同一 episode 的其他有效片段，不整条排除。
- 无可用包或时长为零的片段不进入片段分类训练和评估，单独报告排除数量、类别分布和覆盖率；暂不增加最少包数或最短时长门槛。
- 首版排除无法可靠对齐的标注区间并记录原因，保留其余有效片段；全面修复时间对应关系不作为首版完成条件。
- 两个任务的 MTAM 字节量统一使用 IP 包总长度，包含 IP 头、运输层头和数据，不包含链路层头。
- 保留纯 ACK、无数据的 SYN/FIN 等控制包，计入 MTAM 的包数和字节量。
- 保留捕获中实际观察到的 TCP 重传，逐包计入 MTAM 的包数和 IP 字节量，不额外做 TCP 重传过滤。
- 纳入能够确定运行端方向且能可靠读取 IP 总长度的 IPv4/IPv6 包，不限于 TCP，可包含 UDP、ICMP 等；ARP 等非 IP 包不进入 MTAM。
- 两个任务各自按样本完整时长等分 1800 个槽，输入均为 2×2×1800；不采用固定秒级槽宽后截断的方案。
- 实现原始统计与逐元素 log1p 两种输入配置，各任务独立用验证集比较和选择，测试集不参与选择。
- 两个任务分别使用普通交叉熵作为首版分类损失，不引入类别权重或联合损失。
- 两个任务均以验证集 Macro-F1 选择最佳模型及原始统计/log1p 输入配置，Accuracy 同时报告。
- 主 Macro-F1 仅平均该划分有真实有效样本的类别；片段任务同时附报固定 47 类、缺类计零的 Macro-F1，分类头保持 47 类。
- 首版使用 RF 参考训练参数：Adam、初始学习率 5e-4、weight_decay=1e-3、batch_size=200、30 epochs，沿用 RF 的学习率衰减公式。
- 首版每种配置只用一个固定随机种子，两个任务×两种输入共 4 次训练，不纳入追加种子重复预算。
- 新增独立的 agentprint 模块和命令行入口；两个任务共用适用的预处理和网络定义，分别构建样本、训练、保存权重和评估。
- 术语见根目录 CONTEXT.md；任务边界见 ADR 0001。

## 第二轮：片段质量规则

### Q5 已确认 B：只排除不确定区间

用户选择保留 episode 的其他有效片段。起点重复组的区间为该时间到下一个不同起点，末组到 PCAP 结束；该组全部标注及对应时间范围不构造监督片段，不任意保留其中一条，也不把前后片段跨该范围拼接。原始数据保持完整，排除仅体现在片段样本清单中。此质量规则仅针对 47 类片段任务；episode 场景任务的样本由其自身质量规则决定。

例：10 秒同时标注 N011 和 N014，20 秒标注 N003，则 [10,20) 的单标签归属不确定。已有核验显示，训练集 414 个 codex episode 存在重复起点，排除整条 episode 会连同其中其他可用区间一并丢弃；最终有效片段数须在规则确定后统计。

### Q6 已确认 A：排除无包或零时长片段

在已确认区间规则下，若片段没有可用包或时长为零，则不作为片段训练和评估样本，不以全零 MTAM 替代。报告排除数量、类别分布和覆盖率，保留原始数据与排除原因。

仅包数少、时长短但仍有效的片段不因此排除；暂不额外引入最少包数或最短时长阈值。该规则仅针对片段分类，不能据此自动排除其所属 episode 的场景分类样本。

### Q7 已确认 A：首版允许排除无法可靠对齐的部分

已有探索检查发现部分标注时间不在捕获范围内，另有 Qwen 日志时间以 1970 年形式表示。具体时间基准需核查，不能仅凭年份判断样本失效，也不能猜测偏移量。

首版只纳入能够可靠对齐的片段；无法对齐的部分排除并记录原因和覆盖率，保留同一 episode 其余可用片段。若整个 episode 的日志时间基准都无法确认，则该 episode 暂不能提供监督片段，但不因此失去有目录标签的场景分类资格。时间修复必须有可验证依据，不猜测偏移量；全面修复这些样本不作为首版完成条件。

## 第三轮：MTAM 输入约定

### Q8 已确认 A：字节量使用 IP 包总长度

两个任务的 MTAM 均需为每个包确定一个字节数。备选为 IP 包总长度、链路帧长度、运输层载荷长度。AgentPrint 正文的 packet size 与图注未完全消除此层级歧义，此项属于明确记录的适配选择。

用户确认使用 IP 包总长度，包含 IP 头、运输层头和数据，不包含链路层头；这样可减少不同抓包链路头格式对字节统计的影响。IPv4 对应总长度字段，普通 IPv6 对应固定头长度加其 payload length。该选择不能用链路帧长、捕获字节数或 TCP 载荷长度静默替代。抓包截断等数据质量问题需识别并记录，不能把截断长度冒充原始 IP 包长。

### Q9 已确认 A：保留无运输层载荷的控制包

同一 IP 包长口径下，纯 ACK、无数据的 SYN/FIN 等 TCP 包仍有非零 IP 长度。用户确认保留这些包并计入包数和字节量，两个分类任务使用相同规则。

这一选择保留连接建立、确认与关闭等通信节奏，效果需实验验证。无运输层载荷不等于区间无包，不能以 Q6 为由自动剔除此类包。是否处理重传及非 TCP 协议另行确定。

### Q10 已确认 A：按各样本完整时长等分 1800 槽

论文方法正文将每条 trace 的持续时间均分成 1800 个时间槽。用户确认分别按完整 episode 的捕获时间范围和给定片段的标注区间等分，不因样本较长而截断，不采用固定秒级槽宽后截断或补零的替代方案。

两个任务的输入均为 2×2×1800。例如 180 秒的 episode 每槽 0.1 秒，18 秒的片段每槽 0.01 秒。该选择保留各样本范围内的时间比例，但不同样本每槽对应的绝对秒数不同。片段时间范围取已确认的标注区间，不因首尾无包而自行收缩成首包至末包。

### Q11 已确认 A：验证集比较原始统计与 log1p 输入

包数和字节量的数值范围不同。当前检查的 RF 原始 TAM 提取和训练源码直接使用包数统计，没有显式输入对数变换；该参考模型只有包数通道，不能由此证明 AgentPrint 两统计通道的具体缩放方式。AgentPrint 原文也没有给出明确的输入归一化公式。

用户确认同时实现原始统计与逐元素 log1p 两种配置，分别通过各任务验证集比较后选择。两个任务不要求选出相同的输入变换；各自采用哪种配置由各自的验证结果决定。

log1p(x)=ln(1+x) 保持空槽为零，并压缩大数值；它是否改善 ANT 分类需实验比较，不作为论文已给定设置。比较时固定其余训练条件，最终测试集不参与选配置。

## 第四轮：分类损失与模型选择

### Q12 已确认 A：两个任务分别使用普通交叉熵

两个任务均为独立的单标签多分类。RF 原训练源码明确使用无类别权重的 CrossEntropyLoss；AgentPrint 论文没有明确其具体损失配置。现有标签分布不均衡，但片段质量筛选后的有效样本数尚需重新统计。

用户确认首版两个任务均以普通交叉熵建立基线，不引入类别权重。模型返回 logits，训练使用 CrossEntropyLoss，输出概率时再做 softmax。两个任务分别计算分类损失，不引入联合损失。若未来比较类别加权，应以相应任务的有效训练样本统计为依据，并作为独立实验配置。

### Q13 已确认 A：验证集 Macro-F1 为模型选择主指标

用户确认各任务均以验证集 Macro-F1 选择最佳 checkpoint，并依据同一主指标比较 Q11 的原始统计和 log1p。Accuracy 同时报告，不以测试集成绩选择模型或输入配置。

Macro-F1 让各类别的 F1 等权参与平均，较适合类别数量不均衡时逐类衡量表现。缺失类别的平均口径按 Q14；同分处理另行明确，不能由库默认值隐式决定。

### Q14 已确认 A：有真实样本类别的 Macro-F1 为主

此前原始消息标注核验中，验证集缺 N027、测试集缺 N029；按 Q5–Q7 生成有效片段清单后还需重新统计各类支持数。输出类别仍保持既定的 47 类，不能根据验证或测试缺类而临时删改分类头。

用户确认以当前划分有真实有效样本的类别计算主 Macro-F1；片段任务同时辅助报告固定 47 类、缺类按零计的 Macro-F1。固定类别的缺类计零是约定的辅助统计，不表示已经评估了无真实样本的类别。

参与主平均的类别由该划分固定有效样本清单的真实标签决定，不依赖模型预测；错预测到无真实样本类别的样本仍算原真实类别的漏判。所有模型使用相同评估清单和类别集合，逐类报告支持数、排除情况和覆盖率，避免用不同样本子集直接比较。若实施时发现训练类缺失，须单独报告，不能把无法学习该类的情况隐藏在模型指标中。

### Q15 已确认 A：先用 RF 参考训练配置建立基线

当前 RF 原训练脚本给出 Adam、初始学习率 5e-4、weight_decay=1e-3、batch_size=200、30 epochs，并按 lr(epoch)=5e-4×0.2^(epoch/30) 衰减学习率。它是 RF 的起始配置参考，不能标成已核验的 AgentPrint 原训练配置，也不能认定对 ANT 最优。

用户确认首版先用这组参考参数建立基线，每轮验证并按 Q13–Q14 保存最佳模型。首版不额外开展学习率、批大小等参数的搜索。

Q11 的原始统计/log1p 比较保持其余训练条件一致；若实际硬件无法承载目标 batch size，需显式记录所用配置并保持对应比较一致，不能静默更换参数。当前仍为设计阶段，不启动正式训练。

### Q16 已确认 B：首版单种子，共 4 次训练

用户出于成本考虑选择每种配置只跑一个固定种子，不采用 12 次的全量三种子方案，也不采用 8 次的分阶段补种子方案。

首版采用 seed=42 作为实现默认值；两个任务各比较原始统计/log1p，共 2×2×1=4 次训练。对应输入配置使用相同种子，官方 split 不变，不因种子改变而重划分数据。各次训练按验证主 Macro-F1 选 checkpoint，各任务按本次验证主 Macro-F1 选输入配置；不挑测试成绩，也不报告并未进行的多种子均值和标准差。

目前没有本项目在目标 GPU 上的训练耗时基准，不给出未经测量的分钟数或费用。实际执行前的功能验证不计作完成了上述 30-epoch 正式训练。

## 第五轮：工程组织与其余输入规则

### Q17 已确认 A：独立模块和命令行入口

备选：A 在现有仓库新增独立 agentprint 模块及命令入口，两项任务共享通用流量处理和网络定义、各自训练和评估；B 将新任务和 AgentPrint 模型注册进现有 suite.py / run_all.py 调度。

用户选择 A：在现有仓库新增独立 agentprint 模块及命令行入口，两项任务共享适用的预处理和网络定义，分别构建样本、训练、保存权重和评估。现有套件围绕其既有 baseline 与任务协议组织，独立入口更便于实现当前两项分类任务的数据清单与片段质量规则，也可保留现有 baseline 作为后续对照。可以复用经核验适用的公共解析逻辑，独立任务不等于复制两套处理代码或共享训练权重。

### Q18 已确认 A：保留 TCP 重传

在 Q8 的 IP 包长与 Q9 保留控制包的基础上，另需确定 TCP 重传的计数方式。备选：A 保留捕获中观察到的 TCP 重传，逐包计入对应方向和时间槽的包数、IP 字节量；B 额外识别并过滤 TCP 重传。

用户选择 A：两个任务均保留捕获中实际观察到的 TCP 重传，逐包计入对应方向和时间槽的包数、IP 字节量，不额外做 TCP 重传过滤。保留重传能直接表示观察到的传输流量，不增加依赖 TCP 序列号状态的重传过滤步骤；同时会保留网络条件造成的重传差异，不能预先断言其对分类效果有利。这里讨论网络重传，不等于允许解析器重复读取同一条捕获记录。

### Q19 已确认 A：纳入符合条件的 IPv4/IPv6 包

在 Q2 的 mixed-flow 观察范围与 Q8 的 IP 包长口径下，备选：A 纳入能确定运行端方向、且能可靠读取 IP 总长度的 IPv4/IPv6 包，不按运输层协议仅保留 TCP，因而可包含 UDP（例如其上承载的 QUIC、DNS）和 ICMP 等；B 仅纳入符合相同端点和长度条件的 TCP 包。

用户选择 A：两个任务均纳入能确定运行端方向、且能可靠读取 IP 总长度的 IPv4/IPv6 包，不按运输层协议仅保留 TCP，可包含 UDP、ICMP 等。该选择与观察运行端全部连接的范围一致，避免仅按 TCP 筛选而遗漏可能存在的其他通信；当前未据此断言 ANT 中实际存在何种比例的 QUIC 或其他协议。非 IP 包（例如 ARP）没有已选定的 IP 长度口径，不进入 MTAM；解析失败或无法确定方向的包仍须单独记录，不能作为零长度包计入。运行端识别、方向判定及异常包处理的具体规则另行确定。

### Q20 待决：是否允许自动推断运行端

两个方向需以实际运行 Agent 的端点为参照，不能仅由每条连接的首包方向定义。备选：A 优先核验并使用采集记录或显式端点配置；缺乏明确记录时允许基于固定、可审计的规则自动推断，存在歧义则不强制分配方向，记录并排除受影响样本，也允许补充明确端点配置后重新处理；B 仅接受采集记录或人工确认的运行端地址，不采用启发式推断。

建议 A，尚未采纳。自动推断规则属于 ANT 适配选择，不能标为论文给定方法或已核验真值；具体候选生成、冲突判定及多地址关联需结合采集记录和全量审计确定，并在冻结有效样本清单前明确。两个任务对同一 episode 使用一致的端点依据，不能随片段重新以首包猜测方向。

本轮核验依据为研究工作区的 03_代码/analysis/analyze_ant_boundaries.py 与 02_数据/ANT_边界分析_2026-10-29/episode_quality.json。此前脚本选择出现次数最多的 RFC1918 IPv4 地址，要求该地址覆盖至少 90% 的 IPv4 包；SYN 发起情况只被记录，不是选取条件。172 个有效训练 episode 的最低此类覆盖率约 97.56%，但这是筛选后的训练子集，未包含 codex，且未验证 IPv6；覆盖率不是运行端识别准确率，次数并列时的地址排序也不能作为可靠消歧依据。当前未据此声称服务器完整原始元数据没有端点记录。
